# R039 One-Turn Brush Centerline

Status: geometry gate accepted and formal from-zero H100 training authorized.
R038 remains the last accepted trained result until that run completes.

## Scoped Question

Can the ordinary base strand be represented by length, normalized 3D endpoint
direction, and one guide-owned stiffness field, without stacking a second
low-frequency deformation?

## Schema Change

R039 is intentionally strict:

- `DecodedGroom` contains `brush_stiffness` and no secondary interior field;
- `GroomParameterField` stores `brush_stiffness_raw` only;
- render geometry residuals have no corresponding residual coordinate;
- guide/render lifecycle interpolation, optimizer groups, priors, smoothness,
  checkpoint rows, CLI arguments, launcher arguments, diagnostics, and export
  tools use the same reduced schema;
- an R038 checkpoint cannot be loaded into R039 with `strict=True`.

Frozen R036/R038 configs and records are unchanged. The only executable R039
configuration is `configs/r039_brush_centerline_0_30k.env`.

## Geometry

The endpoint remains `P2 = P0 + L d`. The one-corner reference polyline is
`P0 -> Q -> P2`, where `Q` lies on the root-normal ray at the tip's normal
height. A single quadratic Bezier smooths that corner.

The curve uses the explicit continuous coefficient

```text
direction_difference = ||d - dot(d,n)n||
effective_stiffness = brush_stiffness * direction_difference
```

and interpolates the Bezier control point between the straight midpoint and
`Q`. There is no angular threshold, aligned-direction branch, or second curve
offset.

## Formal Training Schedule

R039 is a strict from-zero, single-variable comparison against R038:

- `brush_stiffness_raw = 0`, hence physical stiffness starts at `0.5`;
- guide roots are frozen through iteration `9000`, so the initial centerline is
  stable during render-root densification;
- at iteration `9001`, guide-owned stiffness starts optimizing together with
  the other guide base fields and uses the existing guide mesh-graph
  smoothness;
- render roots receive interpolated stiffness and have no stiffness residual;
- curl and frizz remain disabled;
- all other training, loss, lifecycle, resolution, and evaluation settings are
  identical to frozen R038.

## Final Absolute-Threshold Audit

The executable R039 source, its frozen environment, and the actual 30k
checkpoint configuration were audited together at commit
`bf8ab2d2b7328894410eb1ad47bfe9b5a407599d`.

- physical length uses a positive, unbounded data-relative asinh/log-ratio
  decoder; there is no absolute minimum, maximum, hinge, or overlength loss;
- root width, width taper, and child radius are likewise positive and
  unbounded in physical units;
- direction is normalized without an angular threshold, and lift is not a
  separately optimized field;
- brush stiffness, opacity, color, tip/root ratio, and clump strength retain
  intrinsic semantic domains rather than animal-specific physical bounds;
- the active render-length prior is a continuous zero-centered residual prior
  with the threshold-free `tail_concentration_handoff` reduction. It does not
  prescribe or clamp physical hair length;
- guide, render, effective-field, and strand-shape smoothness penalize local
  differences continuously. None activates after an attribute crosses a
  fixed value;
- the clean-flow 5%-95% data quantiles and confidence cutoffs are initialization
  evidence rules only;
- densification evidence thresholds, split spacing, and adaptive Gaussian
  segment allocation govern lifecycle or representation capacity only. They
  do not constrain a learned groom attribute;
- curl and frizz physical ranges remain defined for their future semantic
  controls, but both paths are disabled in R039; opacity pruning is also
  disabled.
